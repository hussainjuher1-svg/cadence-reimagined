# Feature decisions

Implementation status refers to the **observed legacy version**. Release decision refers to this release of Cadence. Status labels: `WORKING`, `BROKEN`, `INCOMPLETE`, `DUPLICATED`, `SIMULATED`, `UNNECESSARY`, `NOT FOUND`. Multiple status terms may apply. New-release verification is summarized in `test-report.md`.

| Screen / feature | Intended user & purpose / why it exists | Legacy observed status + evidence | Release decision and rationale | Data path / acceptance check |
|---|---|---|---|---|
| Public homepage | Explain the real interpreter workflow and direct users to sign-in/up | `WORKING` visually but contains demo entry points/claims in monolithic `public/index.html` | **KEEP, simplify** to one hero, Prepare → Work → Review, actual capabilities and boundaries | Static app entry; browser home load and link checks |
| Sign up / sign in / sign out | Create a private local account and secure browser session | `SIMULATED`/`INCOMPLETE` aspects around disclosed demo credentials and seeded account; single smoke test only | **REPAIR** with async password hashing, HTTP-only session cookie, CSRF/origin checks, generic sign-in error | SQLite users/auth_sessions; workflow auth tests, session revoke test |
| Password recovery | Let a user regain access without pretending email was sent | Full legacy flow not independently verified; `INCOMPLETE` evidence is insufficient | **KEEP** local-only flow: hashed single-use 30-minute token; local terminal/outbox mailer; explicit no-email explanation | password_reset_tokens/outbox; reset and session-revocation API test |
| Onboarding | Save display name, languages and time-zone defaults once | `INCOMPLETE` as a persisted end-to-end flow was not proven by old smoke | **KEEP, short and skippable** | users onboarding fields; workflow test saves onboarding |
| Dashboard | Show next action, overdue scheduled work, upcoming and recent real records | `SIMULATED`/`UNNECESSARY` demo stats/activity present in legacy page | **KEEP, simplify**; derives session rows and child counts from SQLite; sample excluded | GET sessions + workspace; test real list and persistence |
| Create / edit / lifecycle | Record required assignment facts and manage status without inventing defaults | `BROKEN` for trust: hard-coded title/client defaults observed near `server.mjs:404`; completion trusts client duration near line 430 | **KEEP, REPAIR** validation, idempotent create, PATCH version, scheduled → in-progress → completed or scheduled → cancelled | sessions + lifecycle API; tests required fields, replay, repeated start, invalid transition and server duration |
| Preparation / primer | Store goals, context, instructions, pronunciation, open questions and truthful checklist | `INCOMPLETE`; not proven by the legacy happy-path test | **KEEP**, derived checklist items plus explicit judgement marks | session_prep/prep_checks; API test round-trips and checklist marks |
| Workspace manual stream | Keep source, interpreted text and notes as ordered user-entered records | `SIMULATED` scripted stream/timeout behavior exists in legacy `public/index.html` | **REPLACE** with persisted manual entry types; no transcription/AI control appears | entries table, owner check; test Unicode/inert-text persistence and edit marker |
| Per-session terminology | Retain source/target terms and context specific to one assignment | Legacy “memory” concept/count is tied to incremented counter behavior (`server.mjs` around 421) | **KEEP per-session; REMOVE cross-session memory** until privacy/reuse rules are designed | terms table; test create/read and owner-denial |
| Follow-ups | Track open actions and resolution time | Not established by old smoke test: `INCOMPLETE` | **KEEP**; text stays editable until closeout; status is a supported closeout action | followups table; test creation, resolved status and completed follow-up update |
| Completion and summary | Close session with server time/duration and show saved content | **BROKEN** for client authority: `server.mjs` around 430 accepts duration/turns from client | **REPAIR** server-authoritative completion; completed core read-only, summary addendum and follow-up status supported | session, entries, terms, followups; reload equality and duration tests |
| JSON/Markdown export | Carry saved record out of the app accurately | Not proven by legacy smoke: `INCOMPLETE` | **KEEP** actual completed record exports only; PDF deferred | API export; test verifies body/type/ownership |
| Sample workspace | Let visitors understand flow without contaminating actual records | Legacy demo path was mixed with normal UI: `SIMULATED` boundary | **KEEP one**, static read-only, fictional, clearly labelled, not persisted or counted | `public/sample.html`; lint checks legacy markers absent from primary client |
| Settings / hard deletion | Set a few preferences and let users remove their data | Not fully established by legacy test: `INCOMPLETE` | **KEEP minimal** with password-confirmed account deletion and cascade | users and FK cascade; workflow deletion test |
| Decorative analytics / fake alerts / progress visuals | Add visual busyness rather than help complete a session | `SIMULATED`/`UNNECESSARY` in legacy view | **REMOVE**; no fake metrics, scripted “live” data, invented activity or fake AI alerts | Lint + direct UI review |
| Interpreter network, clients/invitations, billing, collaboration, AI memory, transcription, AI interpretation, global glossary, PDF export | Future broader product capabilities | No verified implementation needed for current goal | **DEFER**; each needs actual service/security/privacy design and relevant tests. No placeholder UI | Listed in `known-limitations.md`; absent from primary navigation |

### Duplicated information and dead ends

The new workspace keeps language direction, schedule, client label and status in one header/fact area. Repeated marketing feature grids, decorative data cards, fake progress/activity, disabled fake transcription and nonfunctional capability links are removed. No “coming soon” navigation is used for deferred features.


## Product direction update — focused preparation rehearsal

| Feature | Decision | Rationale / acceptance |
|---|---|---|
| Browser-local Preparation Review | **ADD / prototype** | Directly tests the chosen pain point without provider/API dependency. It flags long/complex sentence candidates, figures/units, acronyms and possible capitalized phrases. Heuristics must be labelled and reviewed, not represented as factual analysis. |
| Collapsed sentence practice notes + context hypothesis | **ADD / prototype** | The interpreter enters their own core-claim/condition note for a flagged sentence and optionally their own context-based hypothesis plus evidence/alternative. No semantic prediction is produced. |
| Insert reviewed cues into preparation questions | **ADD** | Reuses existing persisted field and explicit Save preparation action; no schema migration or silent saving. Keep the generated report compact; do not save source sentences automatically; only insert concise user-authored notes after explicit action. |
| One-time fictional example | **ADD** | Lets new users understand tool output without using real client material. Clearly marked fictional and not persisted until the user explicitly chooses to save a report. |
| Packet uploads / document parsing / version diff | **DEFER** | Requires document formats, source/page provenance, safe storage, parser accuracy and version reconciliation. Validate before adding upload controls. |
| AI term/translation generator | **DEFER** | Generic document glossary generation is already served by InterpretBank and other tools. Needs evidence-backed sources, review status and confidentiality policy before any provider integration. |
| Live transcription / translation / speaker anticipation | **DO NOT CLAIM OR SIMULATE** | Not implemented; would add latency, audio access, quality, confidentiality and professional-practice risk. |
| Healthcare briefing / emotional wellbeing / freelancer admin / career qualification | **SEPARATE RESEARCH TRACKS** | Different users and buying processes. Don't expand the first UI until customer evidence proves an adjacent job belongs in the same product. |
